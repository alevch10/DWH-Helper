## Документация модуля S3
> *Версия модуля: 1.0.0*  
### 📌 Описание
Модуль **S3** предоставляет унифицированный интерфейс для работы с S3‑совместимым объектным хранилищем (AWS S3, Yandex Object Storage, MinIO и др.).  
Он реализует клиент на базе `boto3` с поддержкой двух типов подписей:
- `signature_version="s3v4"` – для операций **чтения** (GET, HEAD).
- `signature_version="s3"` – для операций **записи** (PUT, POST, DELETE).

Модуль используется другими компонентами (например, ETL для выгрузки Amplitude, Data Scout для анализа данных) и также предоставляет **REST API** для прямого доступа к хранилищу.

**Основные возможности:**
- Листинг объектов по префиксу (только файлы текущего уровня, без рекурсии).
- Скачивание и загрузка файлов (байтовые данные).
- Проверка существования объекта, получение размера.
- Удаление объектов.
- Разграничение доступа через авторизацию (требуются права `read` для GET, `write` для POST/PUT/PATCH/DELETE).

---

## 🧩 Требования к модулю (из спецификации)

1. Модуль должен устанавливать соединение с S3, используя библиотеку `boto3`.
2. Подпись запросов: `signature_version="s3v4"` для GET‑операций, `signature_version="s3"` для остальных.
3. Предоставлять API с эндпоинтами: GET, POST, PUT, PATCH, DELETE.
4. Роутер должен быть подключён в `main.py` с тегом `S3`.
5. Настройки S3 (access key, secret key, регион, endpoint, bucket) должны быть вынесены в `settings.s3` (через переменные окружения).
6. `.env` должен содержать заглушки для всех необходимых секретов.

## ⚙️ Конфигурация (переменные окружения)

Модуль использует класс `S3Settings` из `app.config.settings` (см. [config.md](../config/config.md)).  
Необходимые переменные окружения:

| Переменная             | Описание                                    | Пример значения                        |
|------------------------|---------------------------------------------|----------------------------------------|
| `S3_ACCESS_KEY_ID`     | Access Key ID (идентификатор)               | `AKIAIOSFODNN7EXAMPLE`                 |
| `S3_SECRET_ACCESS_KEY` | Secret Access Key                           | `wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLE`|
| `S3_REGION`            | Регион хранилища                            | `ru-central1` или `us-east-1`          |
| `S3_ENDPOINT_URL`      | URL S3‑совместимого API                     | `https://storage.yandexcloud.net`      |
| `S3_BUCKET_NAME`       | Имя бакета (контейнера)                     | `dwh-helper-data`                      |

Пример `.env`:
```env
S3_ACCESS_KEY_ID=AKIA...
S3_SECRET_ACCESS_KEY=wJalr...
S3_REGION=ru-central1
S3_ENDPOINT_URL=https://storage.yandexcloud.net
S3_BUCKET_NAME=dwh-helper-data
```

## 🧱 Архитектура модуля

```
app/s3/
├── __init__.py
├── client.py      # S3Client (boto3, два клиента для разных подписей)
└── router.py      # FastAPI эндпоинты
```

### 1. `client.py` – `S3Client`

Инициализирует два клиента `boto3`:
- `self.client_v4` – для GET, HEAD (подпись `s3v4`).
- `self.client` – для PUT, POST, DELETE (подпись `s3`).

Настройки берутся из `settings.s3`.  
Bucket фиксирован (не может быть переопределён в методах – все операции работают в рамках одного бакета, заданного при инициализации).

**Основные методы:**

| Метод                                      | Описание                                                                                     |
|--------------------------------------------|----------------------------------------------------------------------------------------------|
| `list_objects(prefix: str = "")`           | Возвращает список прямых объектов (без вложенных папок) с ключами и датами модификации.      |
| `get_object(key: str) -> bytes`            | Скачивает объект, возвращает байтовое содержимое.                                             |
| `put_object(key, data, content_type=None)` | Загружает объект (создаёт или перезаписывает).                                               |
| `post_object(...)`                         | Алиас для `put_object` (для семантики POST).                                                 |
| `update_object(...)`                       | Алиас для `put_object` (для семантики PUT).                                                  |
| `patch_object(key, data, offset=0)`        | "Частичное обновление" – на практике вызывает `put_object` (S3 не поддерживает истинный PATCH).|
| `delete_object(key)`                       | Удаляет объект.                                                                              |
| `object_exists(key) -> bool`               | Проверяет существование объекта через `head_object`.                                         |
| `get_object_size(key) -> Optional[int]`    | Возвращает размер объекта в байтах (или `None`).                                              |

**Важные детали:**
- `list_objects` фильтрует только файлы, лежащие непосредственно в указанном префиксе (игнорирует вложенные поддиректории). Например, при `prefix = "folder/"` вернёт `folder/file.txt`, но не `folder/subfolder/file.txt`. Сортировка – от старых к новым по `LastModified`.
- Все методы логируют действия через `logger` (уровень INFO).

### 2. `router.py` – HTTP API

Роутер подключается в `main.py` с префиксом `/s3` и тегом `S3`.  
Все эндпоинты защищены зависимостями `require_read` (GET) или `require_write` (POST/PUT/PATCH/DELETE).

#### GET эндпоинты

| Метод | Путь                     | Описание                                                       |
|-------|--------------------------|----------------------------------------------------------------|
| GET   | `/s3/objects`            | Список объектов по префиксу (`?prefix=...`).                   |
| GET   | `/s3/object-info`        | Информация об объекте: размер, существует ли (`?key=...`).     |
| GET   | `/s3/download`           | Скачать объект (возвращает JSON с `data` в hex, неудобно, но для API‑тестов). |

**Ответы:**
- `/objects` → `S3ObjectList` (prefix, count, список объектов с Key/LastModified).
- `/object-info` → `S3ObjectInfo` (key, size, exists).
- `/download` → `{"key": ..., "size": ..., "data": <hex>}`.

#### POST/PUT/PATCH/DELETE

| Метод   | Путь           | Описание                                                             |
|---------|----------------|----------------------------------------------------------------------|
| POST    | `/s3/upload`   | Загрузить файл (multipart/form-data, поле `file`, query `key`).      |
| POST    | `/s3/upload-binary` | (не реализован – возвращает 501)                                    |
| PUT     | `/s3/update`   | Обновить существующий объект (аналогично POST, но семантически PUT). |
| PATCH   | `/s3/patch`    | "Частичное обновление" (query `offset` + файл) – вызывает `put_object`.|
| DELETE  | `/s3/delete`   | Удалить объект (`?key=...`).                                        |

**Формат ответа (для успешных запись):**
```json
{
  "key": "path/to/file.txt",
  "etag": "\"d41d8cd98f00b204e9800998ecf8427e\"",
  "version_id": null,
  "size": 12345
}
```

Удаление возвращает:
```json
{
  "key": "path/to/file.txt",
  "deleted": true
}
```

**Ошибки:**
- 400 – неверные параметры.
- 404 – объект не найден (при GET/UPDATE/DELETE).
- 500 – внутренняя ошибка S3 или клиента.
- 501 – метод не реализован (`/upload-binary`).

## 🔌 Примеры использования

### Листинг объектов (через API)
```bash
curl -X GET "http://localhost:8000/s3/objects?prefix=amplitude_exports/2024/" \
  -H "Authorization: Bearer <token>"
```

### Загрузка файла
```bash
curl -X POST "http://localhost:8000/s3/upload?key=test/archive.zip" \
  -H "Authorization: Bearer <token>" \
  -F "file=@/local/path/archive.zip"
```

### Скачивание объекта
```bash
curl -X GET "http://localhost:8000/s3/download?key=amplitude_exports/2024_week_1.zip" \
  -H "Authorization: Bearer <token>"
```

### Удаление объекта
```bash
curl -X DELETE "http://localhost:8000/s3/delete?key=test/old_file.txt" \
  -H "Authorization: Bearer <token>"
```

### Прямое использование из другого модуля
```python
from app.s3.client import S3Client

s3 = S3Client()
objects = s3.list_objects(prefix="amplitude_exports/")
for obj in objects:
    data = s3.get_object(obj["Key"])
    # обработка data
```

## 🧪 Тестирование

Для тестирования рекомендуется:
- Использовать локальное S3‑совместимое хранилище (MinIO, LocalStack) или мокать boto3.
- В тестах подменять настройки `settings.s3` на тестовые (например, отдельный бакет).
- Проверять поведение `list_objects` с вложенными папками.
- Проверять обработку ошибок (несуществующий ключ, неверные права доступа).

Пример юнит‑теста с `moto` (библиотека для мока S3):
```python
import pytest
from moto import mock_aws
from app.s3.client import S3Client

@mock_aws
def test_s3_put_and_get():
    client = S3Client()  # должен использовать тестовые настройки
    client.put_object("test.txt", b"hello")
    data = client.get_object("test.txt")
    assert data == b"hello"
```

## 🐞 Логирование

Логируются все основные операции:
- Инициализация клиента.
- Каждый вызов `list_objects`, `get_object`, `put_object`, `delete_object` с указанием ключа и (для загрузки/скачивания) размера.
- Ошибки на уровне `ERROR` с трассировкой.

Логгер: `app.s3.client` и `app.s3.router`.

## 🧠 Заметки для разработчиков и ИИ‑агентов

- **Два клиента** – важное требование из ТЗ. В некоторых S3‑совместимых системах (например, Yandex Object Storage) для GET‑запросов нужна подпись `s3v4`, а для PUT – достаточно `s3`. В противном случае могут возникать ошибки `SignatureDoesNotMatch`.
- **Отсутствие истинного PATCH** – S3 не поддерживает частичное обновление объекта. Метод `patch_object` существует только для семантического соответствия API; на практике он полностью заменяет объект. При необходимости можно реализовать составную логику (скачать + изменить + загрузить) в отдельном методе.
- **Безопасность** – все операции требуют аутентификации. Убедитесь, что `require_read` и `require_write` настроены правильно (см. [auth.md](../auth/auth.md)).
- **Эндпоинт `/download` возвращает данные в hex** – это неудобно для больших файлов, но годится для демонстрации и тестирования. В реальных сценариях лучше возвращать `StreamingResponse` с типом содержимого файла. При необходимости можно доработать.
- **Работа с большими файлами** – текущая реализация загружает весь файл в память (`.read()`). Для очень больших объектов рекомендуется использовать потоковую загрузку/выгрузку (например, через `boto3` streaming body). В ETL‑задачах это обычно допустимо, т.к. файлы не превышают сотни мегабайт.
- **Расширяемость** – при добавлении нового хранилища (например, MinIO с другой подписью) можно параметризовать версию подписи через настройки.
